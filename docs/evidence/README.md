# Evidence Directory

Evidence supporting recorded test results (DEC-010): logs, check scripts, screenshots and run summaries, indexed below with what each file demonstrates. Files of the records-consistency checks (TEST-M2-11, TEST-M3-12, TEST-M4-12) are not published; see `docs/testing/test_plan.md`.

## Layout and naming
```
docs/evidence/
├── README.md        this file (policy + index)
├── M0/
├── M1/              (created 2026-10-19 for review-finding evidence; TEST-M1-01 to -08 evidence added 2026-10-19 to 2026-10-21)
├── M2/              (created 2026-10-22 for M2 design-item evidence: OPEN-08 validation, OPEN-09 probe)
├── M3/              (created 2026-11-03 for the M3 feasibility gate, sensors.md §6.1, and the low-obstacle investigation, M3 plan §12; TEST-M3 evidence from Task A on)
├── TA/              (created 2026-11-04: DEC-040 test-automation step, TEST-TA evidence)
├── M4/              (created 2026-11-13: M4 odometry, TEST-M4 evidence)
└── ...
```
File names: `<TEST-ID>_<short-description>.<ext>`, e.g. `TEST-M1-05_frames.pdf`.

## What to commit
- Terminal logs of executed tests (text).
- Screenshots provided by me (PNG), cropped to the relevant content.
- Screenshots and screen recordings of GUI runs (from 2026-11-13, my request) live in the picture gallery [`../gallery/`](../gallery/README.md), sorted by milestone and test ID, not here, and are committed only after I review them (they wait in the git-ignored `docs/gallery/_pending/`); the logs here stay the evidence. Test-run captures (`tools/sim_capture.py`, attempt 1 of a `SHOW=1` run) are named `<log name>_a1_gazebo.png` / `_a1_rviz.png`; re-created demonstrations (`tools/demo_capture.sh`) are labelled `_demo`.
- Diagrams such as `view_frames` and `urdf_to_graphviz` output (PDF/SVG/PNG).
- Small generated files that directly support a result (e.g. a generated URDF/SDF snapshot).
- The exact script that produced a log (`<TEST-ID>_procedure.sh`), when a test was run from a script.
- Plots and the small data files behind them.

Guideline: keep individual files small (roughly under 5 MB). Anything larger needs a reason, recorded in the test entry.

## What not to commit
- ROS bag recordings (`rosbag2_*/`, `*.mcap`, `*.db3`). These are ignored in `.gitignore`.
- Build, install, and log directories; simulator caches; temporary files.
- Redundant raw dumps when a short excerpt plus a summary is enough.
- Anything containing secrets, credentials, tokens, or personal data.

If excluded evidence matters, record its location (path or machine) and a summary in the test entry.

## Rules
- Evidence must be genuine output of the recorded test. Never fabricate, edit for content, or reconstruct evidence after the fact.
- Raw logs are committed byte-for-byte, so they may contain trailing spaces or terminal colour codes. `.gitattributes` exempts `docs/evidence/` from Git whitespace checks for this reason.
- Each file is referenced from its `TEST_RESULTS.md` entry with a statement of what it demonstrates.
- Observations without a file are recorded as "observed by me" in the test entry.
